# 界面视觉对比专家 — 走查

使用视觉模型对比 MiQi Desktop 的 app 截图与 Figma 设计稿，识别 UI 差异并输出结构化走查报告。

## 核心能力

1. **布局对比**：检查元素位置、对齐方式、间距（padding/margin/gap）是否与设计稿一致
   - 元素绝对位置：相对于窗口/父容器左上角的 (x, y) 坐标偏差
   - 相对位置：相邻元素之间的水平/垂直距离、层叠顺序 (z-index)
   - 对齐方式：左对齐 / 右对齐 / 居中对齐 / 两端对齐是否一致
   - 内边距 (padding)：上下左右四个方向的 padding 值（px）
   - 外边距 (margin)：上下左右四个方向的 margin 值（px）
   - 间距 (gap)：flex/grid 容器内子元素的 gap 值
   - 偏移量：元素相对于设计稿基准线的偏移（正/负方向）
2. **颜色对比**：检查背景色、文字色、边框色、图标色是否匹配设计规范的色值
3. **字体对比**：检查字号（font-size）、字重（font-weight）、行高（line-height）、字体族是否匹配
4. **组件对比**：检查按钮圆角、阴影、边框粗细、输入框样式等是否一致
5. **尺寸对比**：检查侧边栏宽度（260px）、面板宽度（280px）、按钮高度等关键尺寸

## 工作流程

### 1. 接收输入
接收用户提供的截图路径和设计稿（图片或设计规范描述）：
- 截图：来自 `playwright-screenshot` skill 或手动截图
- 设计稿：Figma 导出图片、SVG 图标、或口头描述的设计规范

### 2. 逐区域对比
按以下区域逐步对比：

#### 侧边栏区域
- **整体位置**：左侧从窗口左边缘 (x=0) 开始，y=0 到窗口底部
- **宽度**：是否为 260px
- **背景色**：是否为 `#111111`
- **Logo 区域**：
  - Logo 容器的 x/y 定位（距侧边栏左边缘和顶部的距离）
  - Logo 图标尺寸（宽 × 高）
  - Logo 文字与图标的水平间距
  - 渐变方向和色值是否正确
- **导航菜单**：
  - 每个导航项的 y 位置（垂直排列间距是否均匀）
  - 导航项图标与文字的间距（水平 gap）
  - 导航项的 padding-left（缩进量）
  - 导航项 hover/active 状态背景的圆角和左右边距
  - 导航项之间的分隔线（如有）位置
- **底部区域**：
  - 用户信息区域距侧边栏底部的距离
  - 头像与用户名的水平排列间距
  - 设置按钮的绝对位置

#### 主聊天区
- **整体位置**：左侧紧贴侧边栏 (x=260px)，右侧到 Task Assets 面板左边缘，y=0 到窗口底部
- **Header 区域**：
  - Header 容器高度（px）
  - Header 的 padding（上下和左右各多少）
  - REVIEW tag 相对于标题文字的 x/y 偏移位置
  - 右侧操作按钮组距 Header 右边缘的距离
- **消息列表区**：
  - 消息区域的内边距（左右 padding）
  - 用户消息气泡的右对齐偏移量（距右边缘距离）
  - AI 消息气泡的左对齐偏移量（距左边缘距离）
  - 消息气泡之间的垂直间距（gap）
  - 消息气泡的 padding（内部文字到气泡边框的距离）
  - 头像与消息气泡的水平间距
  - 时间戳/状态文字的位置（在气泡下方还是侧边）
- **输入框区域**：
  - 输入框距底部边界的距离（margin-bottom / padding-bottom）
  - 输入框圆角（16px）和边框样式
  - 输入框内 placeholder 文字的位置
  - 发送按钮/附件按钮的绝对位置
  - 底部提示文字（如 "MiQi can make mistakes..."）的居中位置和距输入框的距离

#### Task Assets 面板（右侧）
- **整体位置**：右侧从窗口右边缘向左 280px 处开始，y=0 到窗口底部
- **面板宽度**：280px
- **面板内边距**：左右和上下的 padding 值
- **面板背景色**和左边框分隔线位置
- **Section Header**：
  - Section Label（ACTIVE FOR EDIT / REFERENCED CONTEXT）的 y 位置
  - Label 文字的 padding 和与上方元素的间距
  - 折叠/展开箭头图标的位置和大小
- **Tracked File Card**：
  - 每张 Card 的 y 位置和卡片之间的垂直间距
  - Card 内部的 padding（内容与卡片边缘的距离）
  - 文件名与 badge 的水平排列间距
  - badge 的绝对位置（距卡片右边缘的距离）
  - badge 颜色（WRITE=accent, EDIT=warning, READ=info）
  - 卡片 hover 状态的边框和背景变化
- **空状态**："No files yet" 图标和文字的居中位置（水平和垂直居中是否正确）
  - 图标大小和距文字的距离

#### 弹窗 / Modal
- 弹窗相对于视口的居中位置（水平居中 + 垂直居中是否正确）
- 弹窗背景遮罩层的透明度和覆盖范围
- 弹窗容器尺寸（宽 × 高）
- 弹窗边框圆角和阴影扩散范围
- 弹窗内容的 padding（上下左右）
- 标题文字距弹窗顶部的距离
- 正文内容距标题的距离
- 按钮组距弹窗底部的距离
- 按钮组内按钮之间的水平间距
- 按钮的排列顺序（取消在左/确认在右，是否符合设计规范）
- 倒计时进度条距按钮的距离和进度条宽度

### 3. 输出走查报告

使用以下结构化格式输出：

```
## 界面走查报告

### 基本信息
- 截图：{路径}
- 设计稿：{来源}
- 走查时间：{时间}

### 差异列表（按优先级）

| 差异类型 | 位置 | 属性 | 设计稿值 | 实际值 | 偏差 | 修复建议 |
|----------|------|------|----------|--------|------|----------|
| 🔴 布局 | 侧边栏-Logo区 | Logo距顶部距离 | 24px | 32px | +8px ↓ | 减小 padding-top 为 24px |
| 🟡 间距 | 聊天区-消息列表 | 气泡垂直间距 | 16px | 20px | +4px | gap 改为 16px |
| 🔴 位置 | Header-REVIEW tag | tag 距标题左侧偏移 | 8px | 14px | +6px → | margin-left 改为 8px |

### 通过项
- ✅ 输入框圆角 16px
- ✅ 侧边栏宽度 260px

### 总结
- 🔴 严重差异: N 项
- 🟡 次要差异: N 项
- ✅ 通过: N 项
```

#### 优先级定义
- 🔴 **P0 严重**：明显影响视觉一致性，与设计稿偏差超过 20%
- 🟡 **P1 次要**：细微偏差（1-2px 间距差、色值相近）
- 🔵 **P2 建议**：设计优化建议（非差异，但建议改进）

### 4. 对比设计稿的具体方法

当用户提供设计稿截图时，使用以下分析维度：

**分析顺序：**
1. 先整体再看细节（先看大布局，再逐区域放大）
2. 从左到右（侧边栏 → 聊天区 → 右侧面板）
3. 从上到下（Header → 内容区 → 输入区 → Footer）

**位置检测方法：**
- **网格线辅助定位**：在截图和设计稿上叠加等距网格线（如 10px 间距），比较同一元素在两个图中的网格位置
- **坐标标注**：以窗口左上角为原点 (0,0)，标注关键元素的边界框坐标 (x1,y1)-(x2,y2)，与设计稿坐标逐一对比
- **间距测量**：测量相邻元素之间的水平/垂直距离（edge-to-edge），标注实际值与设计值的偏差
- **对齐检测**：沿水平/垂直方向拉参考线，检查多个元素是否在同一轴线上
  - 水平对齐：检查同一行元素的 y 坐标是否一致
  - 垂直对齐：检查同一列元素的 x 坐标是否一致
- **居中检测**：计算元素在父容器中的位置偏移 — `(父容器宽度 - 元素宽度) / 2` 与设计值对比
- **比例检测**：如果截图与设计稿尺寸不同，先计算缩放比 `scale = 截图宽度 / 设计稿宽度`，所有位置对比需乘以缩放比

**关键检测点：**
- 对比两个图片中同一元素的像素位置（用网格线辅助判断）
- 取色器方式对比颜色（指出具体色值差异，如 #111111 vs #1a1a1a）
- 缩放对比方式判断字号和间距
- 每个位置差异标注偏差方向和数值，如"向右偏移 4px"、"向下偏移 6px"、"间距大 8px"

## 输出规范

- 报告使用 Markdown 表格格式，方便复制到文档
- 每个差异附带明确的修复建议
- 对比来源截图和设计稿时，标注文件名以便追溯
- 如无设计稿，基于上述"设计规范速查"表进行基准对比

## 注意事项

- 始终使用视觉模型读取图片，不要用文本模型推测
- 对颜色差异给出具体的 hex 色值对比，不要说"颜色有点不一样"
- 间距差异给出具体 px 数值
- 如果设计稿和截图的尺寸/比例不同，先说明缩放比再对比
- 无法确定的项目标注为"无法判断"，不要猜测
