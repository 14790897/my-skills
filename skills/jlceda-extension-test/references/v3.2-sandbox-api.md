# EDA V3.2 Sandbox API Reference

JLCEDA V3.2 (since ~2025-08, version like V3.2.148) split the extension API
across **two locations** instead of the V3.0 blob-frame + `window.eda`
model. This file documents what changed and how to work with it.

**Verified on:** local-netlist-analyzer v1.3.5 against JLCEDA Pro V3.2.148
(`https://pro.lceda.cn/editor`), via Playwright CDP on Edge 150 (mcp-launched
profile, debug port 9269).

## Where `eda` lives in V3.2

```
window._EXTAPI_SCRIPT_SPACES_  // global Map of all extension sandboxes
  └─ [extensionUuid]            // your extension's sandbox, e.g. "7bdb0024..."
       ├─ eda                   // the API object you actually use
       ├─ document, navigator   // ... and other sandbox globals
       └─ (window, fetch, etc.)
```

The `eda` object inside the sandbox has **all the methods you need**, but
`Object.keys(eda.sch_SelectControl)` returns `[]`. The methods are on the
**prototype chain**, not own properties.

```js
// 探测 eda 方法 (从主页面)
const spaceKey = '<your extension uuid>';
const eda = window._EXTAPI_SCRIPT_SPACES_[spaceKey].eda;

// 错误 (永远空):
Object.keys(eda.sch_SelectControl);  // []

// 正确:
Object.getOwnPropertyNames(Object.getPrototypeOf(eda.sch_SelectControl));
// → ['getAllSelectedPrimitives_PrimitiveId', 'getAllSelectedPrimitives',
//    'getSelectedPrimitives_PrimitiveId', 'getSelectedPrimitives',
//    'doSelectPrimitives', 'doCrossProbeSelect', 'clearSelected',
//    'getCurrentMousePosition', 'getAllSelectedPrimitives3']
```

## Key API differences vs V3.0

| V3.0 | V3.2 |
|------|------|
| `eda` directly in main page | `eda` only in `_EXTAPI_SCRIPT_SPACES_[uuid].eda` |
| `eda.sch_SelectControl.getAllSelectedPrimitives()` returns own-prop methods | Same method names, but on prototype — use `Object.getPrototypeOf` to enumerate |
| `getState_PrimitiveType()` returns `'COMPONENT'` (string) or `6` (number) | Returns `'Component'` / `'ComponentPin'` / `'Wire'` etc. (V3.2 ESCH_PrimitiveType enum, ALL string, mixed case) |
| `pin.getState_OwnerComponentDesignator()` exists | **REMOVED** — use `eda.sch_PrimitiveComponent.getAllPinsByPrimitiveId(primitiveId)` to find which component owns a pin by its primitiveId |
| `extension.json.headerMenus` works for top menus | Top menus still work, but for **right-click menus** you also need `extension.json.contextMenus` |
| `eda.sys_HeaderMenu.insertHeaderMenus(...)` available | Same (BETA), but for runtime registration |

### ESCH_PrimitiveType enum values (V3.2)

```ts
enum ESCH_PrimitiveType {
  ARC = "Arc", BUS = "Bus", CIRCLE = "Circle",
  COMPONENT = "Component",         // ← V3.2 string, NOT 'COMPONENT' or 6
  COMPONENT_PIN = "ComponentPin",  // ← pin on a component (sub-primitive)
  PIN = "Pin",                     // ← pin on a symbol (sub-primitive)
  POLYGON = "Polygon", RECTANGLE = "Rectangle",
  TEXT = "Text", WIRE = "Wire", OBJECT = "Object",
  BEZIER = "Bezier", ELLIPSE = "Ellipse", ATTRIBUTE = "Attribute"
}
```

## Pin-to-component reverse lookup (V3.2 way)

```js
// Given: selected pin primitiveIds (from getAllSelectedPrimitives)
// Goal: find which component designator each pin belongs to

const allComps = await eda.sch_PrimitiveComponent.getAll();
for (const c of allComps) {
  const desig = c.getState_Designator();           // e.g. "U1"
  const compPrimId = c.getState_PrimitiveId();     // e.g. "abc123"
  const pins = await eda.sch_PrimitiveComponent.getAllPinsByPrimitiveId(compPrimId);
  for (const p of pins) {
    const pid = p.getState_PrimitiveId();
    if (selectedPinPrimIds.has(pid)) {
      // pin `p` belongs to component `desig`
      includeDesigs.add(desig);
    }
  }
}
```

**Common mistake**: calling `pin.getState_OwnerComponentDesignator()` — this
method does NOT exist in V3.2. The official pro-api-types 0.3.6 confirms it.

## Right-click menu registration

V3.2 supports two ways:
1. **Static** in `extension.json`:
   ```json
   {
     "contextMenus": {
       "sch": [
         {
           "id": "my-ctx",
           "title": "我的右键",
           "menuItems": [
             { "id": "analyze", "title": "分析", "registerFn": "analyzeSelection" }
           ]
         }
       ]
     }
   }
   ```
2. **Dynamic** at runtime via `eda.sys_RightClickMenu.changeMenu(menuId, items)` (BETA).

Both require the `registerFn` to be exported from your `src/index.ts` entry.

## Top-level eda globals (verified working in V3.2.148)

The following methods can be called from main page via
`_EXTAPI_SCRIPT_SPACES_[uuid].eda.<module>.<method>()`:

| Module | Working methods (verified) |
|--------|---------------------------|
| `eda.sys_IFrame` | `openIFrame(htmlFileName, w, h, id, props) → Promise<boolean>`, `closeIFrame(id)`, `isIFrameAlreadyExist(id)` |
| `eda.sys_Dialog` | `showInformationMessage(msg, title)`, `showConfirmationMessage(msg, title)`, `showInputDialog(opts)`, `showSelectDialog(opts)` |
| `eda.sys_Storage` | `getExtensionUserConfig(key)`, `setExtensionUserConfig(key, value)` |
| `eda.sys_FileSystem` | `saveFile(blob, filename)` |
| `eda.sys_HeaderMenu` | `insertHeaderMenus(headerMenus)`, `replaceHeaderMenus(headerMenus)`, `removeHeaderMenus()` |
| `eda.sys_RightClickMenu` | `changeMenu(menuId, menuItems)` (BETA) |
| `eda.sch_SelectControl` | `getAllSelectedPrimitives_PrimitiveId()`, `getAllSelectedPrimitives()`, `clearSelected()`, `doSelectPrimitives(ids)`, `getCurrentMousePosition()` |
| `eda.sch_PrimitiveComponent` | `getAll(componentType?, allPages?)`, `getAllPinsByPrimitiveId(primitiveId)`, `get(primitiveId)`, `modify(primitiveId, props)` |
| `eda.sch_PrimitiveWire` | `getAll()` |
| `eda.sch_PrimitiveText` | `getAll()` |
| `eda.sch_ManufactureData` | `getNetlistFile(fileName, netlistType)` — netlistType: 'JLCEDA' / 'Protel2' / 'EasyEDA' |
| `eda.sch_Document` | `getPrimitivesInRegion(left, right, top, bottom)`, `navigateToRegion(...)`, `save()` |

**Important**: most sch methods need the schematic canvas to be **active** (i.e.
the user must have opened the sch tab). If you call them from main page via
the proxy while no sch is open, they may throw "获取所有器件失败" or return empty.

## Debug mode URL

Adding `?cll=debug` to the editor URL enables the extension's `console.log`
output to be visible in DevTools. Press F12 three times to open DevTools.

This does NOT make `eda` available in main page — the sandbox injection is the
same; `cll=debug` only makes logs visible.

## Common V3.2 errors and fixes

| Error | Cause | Fix |
|-------|-------|-----|
| `Object.keys(eda.sch_SelectControl)` returns `[]` | Methods on prototype, not own | Use `Object.getPrototypeOf(eda.sch_SelectControl)` to enumerate |
| `pin.getState_OwnerComponentDesignator is not a function` | V3.2 removed it | Use `getAllPinsByPrimitiveId(primitiveId)` to reverse-lookup |
| `getState_PrimitiveType()` returns nothing | Called on wrong context (main page proxy) | Call inside the extension bundle (which has `eda` in scope) or via `_EXTAPI_SCRIPT_SPACES_` |
| `获取所有器件失败` | sch canvas not active | User must open the sch tab first |
| Top menu shows but click does nothing | Function not exported from `src/index.ts` | Add `export function yourFn() { ... }` to entry |
| Right-click menu missing | `extension.json` has no `contextMenus` | Add `contextMenus.sch.<groupId>.menuItems` |
| `cll=debug` page never receives new eda after import | Need real F5 in user's browser | Tell user to press F5; `page.reload()` does NOT recover |

## How the extension code is loaded (verified)

```
mcp dev_plugin  →  upload .eext  →  EDA injects as <script> in worker
                                →  worker has `var eda = <remoteAPI>`
                                →  worker exports activate(), etc.
                                →  EDA wraps in _EXTAPI_SCRIPT_SPACES_[uuid]
```

So your `src/index.ts` can use `eda` directly (no `import` needed). The reason
you see `_EXTAPI_SCRIPT_SPACES_[uuid].eda` from the main page is because EDA
**also exposes a proxy** of the same object to the main page for debugging.
