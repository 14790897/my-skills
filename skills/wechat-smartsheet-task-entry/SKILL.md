# 腾讯智能表任务录入

## 适用对象

- 文档：内部「任务进度与需求统计表」（腾讯/微信文档 智能表）。文档 URL、表名、tab id
  均为内部信息，使用时按实际环境替换（`<smartsheet-url>`、`<主表tabId>`）。
- 主表：**主表**（内部表名略；tab id 形如 `<tabId>`）——任务只加在这里，
  用户明确要求「只进主表」。
- 其他工作表：仪表盘表（只读统计）、分析报告表。**不要新建工作表。**
- 负责人列显示为「研发」，默认填**本人**（表里用真实姓名，注意别写错字）。
- 工具：`browsermcp` 操作已登录的用户 Chrome（不要用 headless / preview 浏览器）。

## 关键机制（先读再动手）

1. **表格是 canvas 渲染**：文字不在 DOM 里，只能截图看或经「记录抽屉」读；不要指望 `innerText` 或 ARIA 拿行数据。
2. **工作表切换**：侧栏项是 DOM，`document.querySelector('#sheet-component-<tabId>').click()` 可切表。tab id 用
   `Array.from(document.querySelectorAll('[id^="sheet-component-"]')).map(e => [e.id, e.innerText])` 现查。
3. **行号区**：canvas 左侧行号列，CSS x≈240（窗口 2504×893 时）；行高约 30–41 CSS 随行高设置变化。
   截图是缩略图（1568 宽 ≈ CSS×1.6），**坐标每次都不同，永远用「展开记录」标题核对目标行，不要盲信坐标**。
4. **行菜单**：在行号区右键 → 菜单含「展开记录 / 添加子记录 / 创建副本 / 向上插入 / 向下插入 / 删除」。
   判断是不是行菜单：**有「展开记录」才是行菜单**；侧栏工作表右键是另一套（重命名/删除等）。
5. **记录抽屉**（行菜单→展开记录）：右侧打开 DOM 表单，标题 = 任务描述值，可读可改：
   项目名称/所属模块、任务类别、任务描述、研发（成员）、状态、优先级、任务提出时间、计划上线时间等。
   全部改动**自动保存**。
6. **状态是单选**：点抽屉里的「状态」combobox（browsermcp 真实 click 有效；合成的 mousedown 序列对部分控件无效）→
   弹出选项：完成 / 需求提出 / 策划中 / 测试中 / 开发中 / 验收中 / 关闭 → 点目标项。
7. **复制/粘贴整行**：选中行号 `Control+c`，到目标表选中行号 `Control+v`。
   粘贴**覆盖所选行**（不是插入），且**不携带「状态」列**——粘完必须单独补状态。
   - 行号在 canvas 上，**x 随水平滚动变化**（任务描述在最左时 CSS x≈220，窗口 2504×893）。
     右键试开菜单：**出现「展开记录」才说明命中行号**；左键同一点选中整行，
     右下角出现「已选择记录 1 计数 15」之类的提示即选中成功。
   - **「添加一行」总是插在当前活动行上方，不会追加到末尾**。活动行还停在
     第 1 行时点它，会把整表顶下去、所有行号 +1；不要用它来「加到底部」。
   - **行尾插入**：选中最后一行 → 行菜单 →「向下插入」，才会在该行之后追加；
     这是末尾加行的正确入口。
8. **行号是视图序号**：「进度状态」视图按状态分组展示，改状态会让行号重排。
   不要用旧截图里的行号定位记录，用内容/抽屉标题核对。

### 抽屉字段定位与选项

- 用 eval 给右侧可见的 `[role=combobox],[role=listbox]` 按 y 排序赋临时 id；顺序：
  项目名称/所属模块(0)、任务类别(1)、状态(2)、优先级(3)、涉及端(4)、需求来源(5)。
- `.text-editor` 按 y：任务描述、需求提出方、备注；日期 input：
  任务提出时间、计划上线时间、研发开始时间（+ HH:mm）。
- **「剩余时间」是公式字段**（如「1 个工作日前已截止」），没有手填的「完成时间」；
  表达「完成日今天」= 状态设为「完成」+ 计划上线时间设为今天。
- 常用选项（**具体取值按实际表格**，这里只列形态）：
  - 项目：多个内部项目名，多选（可同时挂两个，如「项目A + 项目B」）
  - 类别：宣传 / 调研 / 测试 / 产品 / 开发
  - 状态：完成 / 需求提出 / 策划中 / 测试中 / 开发中 / 验收中 / 关闭
  - 优先级：P2 / P0 / P1
  - 涉及端：MAC / WIN
  - 需求来源：需求对接 / 定期组会 / 老板要求 / 实验室 / 运营中心 等（内部来源名，按实际取值）

## 标准流程

### A. 新增今天的一批任务（推荐做法）

1. 打开主表。
2. 找一行同结构的历史任务作模板：行号右键 → 展开记录，确认内容结构。
3. 对每条新任务：
   - 复制模板行 → 粘贴到一条空行（选中该空行行号再 Ctrl+V）；
   - 行菜单 → 展开记录，改 任务描述、项目名称/所属模块、任务类别、优先级、任务提出时间/计划上线时间；
   - 研发 = 本人（空的话点研发字段，在成员搜索里选人名）；
   - 状态按需设置（流程见上）；
   - **用抽屉标题核对**：标题应等于新任务描述，改完再关。
4. 全部完成后逐条复核（见 C）。

### B. 修改单条记录某个字段（如状态）

1. 定位记录（找关键词跳转：点「查找替换」搜任务描述原文，画布会滚动并高亮命中行），
   或逐行右键 + 展开记录核对标题。
2. 展开记录 → 改字段（状态：点 combobox 选「完成」）→ 关抽屉。
3. 复核（见 C）。

### C. 复核（必做）

- 重新展开该记录的抽屉，读字段值；或**刷新页面后再读**。
- 保存偶发静默失败（控制台大量 503 时尤其危险）——**UI 里的“已显示完成”不等于服务器已保存**；
  曾出现 3 条状态丢失。
- 仪表盘表的统计（任务总数/已完成数）是服务器数据的旁证。

### D. 删除

- 删行：行号右键（确认菜单有「展开记录」）→「删除」。删除前先展开记录核对标题，防止错删。
- 删工作表：侧栏工作表右键 →「删除」→ 确认框标题写「删除智能表」，实际只删所选工作表；**确认前先看清楚右键的是哪个工作表**。

### E. 把记录移动到底部 / 恢复行序

1. 选中源行行号（右键能开「展开记录」的那个 x/y）→ `Control+C`；
   右下角出现「已选择记录 …」再复制。
2. 用 `WheelEvent(deltaY)` 滚到底部，选中目标空白行行号 → `Control+V`。
   粘贴覆盖该空白行，**状态列不会带过去**，必须重新展开记录补「状态」。
3. 如果「添加一行」在顶部多插了空白行、导致所有行号 +1：
   - 右键该行行号 → 展开记录，确认字段**全空**（全是「请选择/请输入」，剩余时间「-」）；
   - 关闭抽屉 → 再右键同一行 → 删除；
   - 用「查找替换」搜一个已知任务标题，确认行号回到原值，记录数也恢复。
4. 搜索显示「1/2」时先按 Enter 看第二处：可能是同一行的任务描述 + 备注，**不一定是重复记录**。

## 已知坑

- **「添加一行」总是插在当前活动行上方**（活动行在第 1 行时会顶到最顶部），不要用它来“加到底部”；
  如果已经用了并留下空白行，按 E.3 核对后删除。
- **键盘滚动不可靠**：搜索框/抽屉有焦点时 `Control+End`、`ArrowDown` 不会移动画布；
  用 `WheelEvent(deltaY)` 派发到 canvas 滚动，向上用负值。
- **日期输入会弹日期选择器**，覆盖下面一行；输入后按 Escape 或点其它标签关闭，
  再操作下一个控件，否则会报 “#tmp-input-x is covered by div”。
- **删除空白行前必须展开记录确认全空**；删除后用「查找替换」核对已知行号与记录数，确认没有错删。
- **「导入表格」会新建工作表**，不会追加到主表；「追加导入数据」入口经常不可用。用户拒绝这种做法，别用。
- 批量粘贴容易错行：粘贴覆盖的是“当前选中行”，选错一行就覆盖了别的任务。粘贴后必须逐条核对。
- 空白行是显示占位：选中空行粘贴即可写入；不要用「向上插入/向下插入」造行。
- 底部行附近坐标容易差一行：右键后先看「展开记录」打开的标题再决定是否操作。
- 数字/日期列粘贴为文本时格式可能不一致，优先在抽屉里改。
- 版本历史（文件操作 → 版本历史记录）只有「谁、何时」，没有逐格明细；
  「文档动态」只记录负责人变更和自动化提醒；「浏览记录」记录谁看过。查改动明细只能靠版本快照对比，且子版本预览不一定切换内容，成本很高。
- 版本预览时画布在内嵌 iframe 里：滚轮事件要用 **iframe 自己的 WheelEvent 构造器**派发（父页面的 MouseEvent 会报错），关掉历史面板才回到可编辑层。

## 交付时的说法

- 报告里写清：加了哪几条（任务描述、类别、优先级、负责人、日期），以及**复核结果**（服务器侧读到的一致状态）。
- 有失败/未保存的，如实说明并补做，不要按“应该已保存”上报。
