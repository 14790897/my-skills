# BOSS直聘 · 真实浏览器投递演示（windows-mcp）

2026-11-15 实测：Windows 11、3840×2160 物理分辨率 @200% 缩放、用户真实 Chrome、windows-mcp 真实输入。

## 硬约束（用户定的）

- **只输入、不发送**：介绍文字只打进聊天输入框，绝不回车、绝不点「发送」。
- **隐私**：真实姓名/头像不能出现在画面里；也不要在对话里复述账号信息。
- Claude 与 Chrome **并排**，Chrome 不全屏（用户在录屏，要同时看到两边）。
- 录屏由用户自己录。

## 一、坐标口径（第一次失败就在这）

- windows-mcp 的截图是 1920×1080 的**逻辑图**；鼠标坐标 = 截图像素 ×2（物理 3840×2160）。工具返回头里写的 `Scale 2.0` 就是这个。
- **不要背死坐标。** 任何一条横幅的出现/消失都会让整页平移：
  - Chrome 书签栏、扩展信息条、"恢复页面"气泡；
  - BOSS 自己的顶部公告/登录提示条；
  - 页面缩放（Ctrl+- 一次 = 90%）、窗口位置与大小。
- 本次事故：开头关掉了顶部横幅，JD 页「立即沟通」实际在 `(3608,657)`，却按旧量法点了 `(3086,588)` —— 落在空白处。连续 7 个岗位的「沟通」没点开、介绍文字也没进输入框，而 **`Type` 工具照样返回"已输入"**：它只报告"在坐标处敲了字"，**不管那里有没有输入框**。

### 三个可靠信号

1. `Snapshot(use_dom=true)` 输出浏览器可访问性树，**每个可点元素都带真实屏幕坐标**（例：`链接 "立即沟通" (3608,657)`）。要按钮坐标就从树里取，不要量像素。
2. **截图只用来验证结果**，不用来定坐标。验证点：聊天页右上出现「招聘者姓名 + 公司 + HR职位」+ 岗位标题行；页面底部输入框里有你打的字；右侧没有我方消息气泡。
3. 若走 chrome-devtools MCP 的 CDP 模式（见第四节），连坐标都不用取：`take_snapshot` 给每个元素 `uid`，直接按 uid 点击。

## 二、键盘：绝对不要用全局快捷键

- `Shortcut` 是系统级 SendInput，**落在当前前台窗口**。Chrome 没聚焦时按 `Ctrl+W`，关掉的是 **Claude 自己的对话标签**（本会话已多次发生，用户明确不满）；`Ctrl+Shift+A`、`Alt+F4` 同理会打到 Claude 上。
- 需要 Back/前进：**先 Click 一下 Chrome 里无害的空白处**（例如工具栏空白、聊天区留白）再发 `Shortcut`；能点页面内元素就不要用快捷键。
- BOSS 的 SPA：已沟通岗位从结果列表消失、列表重排；从聊天页 `Alt+Left` 回结果列表后**必须重新按文字定位**下一个岗位，旧坐标全部作废。

## 三、端到端流程

1. 搜索：`嵌入式软件`（上海）有效；`计算机` 会搜出客服/录入/直播等杂岗，别用。
2. 过滤：卡片左上角「猎头」「代招」角标 = 代招/外包；详情右侧招聘者写「猎头顾问」或挂「去App」的也跳过。优先 在校/应届、经验不限、公司直招（有真实公司名与 logo）。
3. 点卡片 → 右栏出 JD（标题行 + 收藏 / 立即沟通 / 举报）。
4. 点「立即沟通」→ 进入 `/web/geek/chat` 的对应会话（顶部显示 姓名+公司+HR职位+岗位）。
5. 输入框在窗口底部（本布局屏幕坐标 ≈ `(2400,1920)`）；用 `Type` 的 `loc` 参数（会先点击再输入），中文可直接键入；**永远不带 `press_enter`**。
6. 截图验证：输入框有字、无我方气泡（只有平台 PK 卡片）。
7. `Alt+Left` 回列表 → 列表刷新 → 用 `Snapshot(use_dom=true)` 按岗位标题文字重新定位下一张卡片。
8. 数量：单日约 20 个新会话未见明确限流，但列表偶有不刷新，重试即可。

## 四、反调试：CDP 默认会被打，但可以绕过（2026-11-15 更新）

- 裸挂 `chrome.debugger` / CDP（browsermcp、chrome-devtools MCP 默认模式）会触发 disable-devtool：标题在 `Loading …` 与真标题间跳、`console.table` 刷屏、最终白屏或关标签。
- **绕法**：chrome-devtools MCP 的 `navigate_page(initScript=…)` 在页面脚本执行前注入——把 `console.table/dir/dirxml/group/…` 覆盖成 no-op，并只对这几个函数让 `Function.prototype.toString` 返回 `[native code]`。注入后**搜索结果页和 `/web/geek/chat` 都能正常加载**（2026-11-15 15:00 实测，聊天页不再重载）。
- 前提：MCP 以 `--autoConnect` 挂在**真实 Chrome** 上（需先在 `chrome://inspect/#remote-debugging` 打开 Remote debugging 开关），否则是空 profile、没有登录态。**每次"新文档"导航都要重新带 initScript**；同页 SPA 路由切换不需要。
- CDP 模式最大的好处：`take_snapshot` 给每个元素一个 `uid`，点击/填表直接用 uid（`click(uid=…)`），**完全不依赖像素坐标**，第一节的坐标漂移问题直接消失。代价：薪资在 DOM 里是 PUA 字形，读出是空的（`-K`），要价格仍得看画面或走 `/wapi` 接口。
- browsermcp 没有"导航前注入"的时序（`goto` 后页面脚本已跑完），所以对 BOSS 不如 chrome-devtools MCP。

## 五、隐私遮挡（录屏）

- 办法：Tk 无边框 topmost + `WS_EX_TRANSPARENT`（点击穿透）遮罩窗口盖住页头姓名/头像。
- Tk 进程 DPI 不感知 → 实际位置 = geometry ×2；用 `MoveWindow` 精确对齐截图上量到的页头坐标。
- **OBS「窗口捕获」只录 Chrome，不含独立遮罩窗口**；遮罩要入镜必须用显示器捕获，或在 OBS 里加滤镜遮罩。
- 聊天页页头、左侧会话列表顶部也会显示名字——遮罩要覆盖整个页头，而不是只盖头像。

## 六、自动打招呼

- 必须在 App 里关掉「自动打招呼」，否则点「立即沟通」会直接发出预设消息，违背"不发送"。
- 判断方法：新会话里如果我方气泡不存在（只有 PK 卡片）即说明已关闭；一旦看到自己发出的消息立刻停手并告知用户。
